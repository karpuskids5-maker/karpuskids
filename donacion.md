PLAN ESTRATÉGICO Y ARQUITECTURA TÉCNICA — SISTEMA DE DONACIONES Y RECAUDACIÓN DE FONDOS
Karpus Kids Ecosistema V5.0 — Integración Comercial (index.html) y Panel Directora (panel_directora.html)

📄 1. RESUMEN EJECUTIVO Y OBJETIVOS
El presente Plan Estratégico define la especificación de arquitectura, base de datos, experiencia de usuario (UX) e integración tecnológica para implementar un Módulo Integral de Donaciones y Filantropía en el ecosistema Karpus Kids.

El sistema permitirá al colegio y a la fundación asociada captar fondos para equipamiento escolar, becas para niños de escasos recursos, mejoras de infraestructura y programas de nutrición.

Componentes Clave:
Frontend Público (index.html): Portal de campañas activas, calculadora de montos, formulario de donación y emisión instantánea de referencias de seguimiento.
Backend Serverless (Supabase & Deno): Tablas PostgreSQL con Row Level Security (RLS), procedimientos almacenados (RPC) y generación de recibos PDF.
Panel Administrativo (panel_directora.html): Centro de comando para crear campañas, auditar ingresos, aprobar transferencias, gestionar donantes y exportar certificados de donación deducibles de impuestos.

2.2 Componentes del Portal Público

Título de la causa (Ej. "Beca de Estudios Karpus 2026", "Remodelación Patio de Juegos").

Tarjeta de Crédito / Débito: Procesamiento instantáneo vía pasarela.

🗄️ 4. MODELO DE BASE DE DATOS SUPABASE (POSTGRESQL)
Se ejecutarán las siguientes tablas y procedimientos almacenados en la base de datos PostgreSQL:

-- 1. TABLA DE CAMPAÑAS DE DONACIÓN
CREATE TABLE IF NOT EXISTS public.donation_campaigns (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  target_amount NUMERIC(12,2) NOT NULL DEFAULT 0.00,
  raised_amount NUMERIC(12,2) NOT NULL DEFAULT 0.00,
  cover_image_url TEXT,
  start_date DATE NOT NULL DEFAULT CURRENT_DATE,
  end_date DATE,
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. TABLA DE REGISTRO DE DONACIONES
CREATE TABLE IF NOT EXISTS public.donations (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  tracking_ref TEXT UNIQUE NOT NULL, -- Ej: DON-2026-X89F
  campaign_id BIGINT REFERENCES public.donation_campaigns(id) ON DELETE SET NULL,
  donor_name TEXT NOT NULL,
  donor_email TEXT NOT NULL,
  donor_phone TEXT,
  donor_tax_id TEXT, -- Cédula o RNC
  is_company BOOLEAN DEFAULT false,
  is_anonymous BOOLEAN DEFAULT false,
  amount NUMERIC(12,2) NOT NULL CHECK (amount > 0),
  currency TEXT NOT NULL DEFAULT 'DOP',
  payment_method TEXT NOT NULL, -- transfer, card, cash
  bank_name TEXT,
  receipt_url TEXT, -- Volante subido
  status TEXT NOT NULL DEFAULT 'pending', -- pending, approved, rejected
  notes TEXT,
  approved_by UUID REFERENCES public.profiles(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3. PROCEDIMIENTO ALMACENADO PARA REGISTRAR DONACIÓN CON REF ÚNICA
CREATE OR REPLACE FUNCTION public.register_donation(
  p_campaign_id BIGINT,
  p_donor_name TEXT,
  p_donor_email TEXT,
  p_donor_phone TEXT,
  p_donor_tax_id TEXT,
  p_is_company BOOLEAN,
  p_is_anonymous BOOLEAN,
  p_amount NUMERIC,
  p_payment_method TEXT,
  p_bank_name TEXT,
  p_receipt_url TEXT
) RETURNS JSONB AS $$
DECLARE
  v_ref TEXT;
  v_donation_id UUID;
BEGIN
  -- Generar código de seguimiento único
  v_ref := 'DON-' || TO_CHAR(NOW(), 'YYYY') || '-' || UPPER(SUBSTRING(MD5(RANDOM()::TEXT) FROM 1 FOR 6));
  
  INSERT INTO public.donations (
    tracking_ref, campaign_id, donor_name, donor_email, donor_phone,
    donor_tax_id, is_company, is_anonymous, amount, payment_method,
    bank_name, receipt_url, status
  ) VALUES (
    v_ref, p_campaign_id, p_donor_name, p_donor_email, p_donor_phone,
    p_donor_tax_id, p_is_company, p_is_anonymous, p_amount, p_payment_method,
    p_bank_name, p_receipt_url, 'pending'
  ) RETURNING id INTO v_donation_id;

  RETURN jsonb_build_object(
    'success', true,
    'donation_id', v_donation_id,
    'tracking_ref', v_ref,
    'message', 'Donación registrada correctamente'
  );
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- 4. PROCEDIMIENTO ALMACENADO PARA APROBAR DONACIÓN (ACTUALIZA CAMPAÑA)
CREATE OR REPLACE FUNCTION public.approve_donation(
  p_donation_id UUID,
  p_approver_id UUID
) RETURNS JSONB AS $$
DECLARE
  v_amount NUMERIC;
  v_campaign_id BIGINT;
BEGIN
  UPDATE public.donations
  SET status = 'approved', approved_by = p_approver_id
  WHERE id = p_donation_id AND status = 'pending'
  RETURNING amount, campaign_id INTO v_amount, v_campaign_id;

  IF FOUND AND v_campaign_id IS NOT NULL THEN
    UPDATE public.donation_campaigns
    SET raised_amount = raised_amount + v_amount
    WHERE id = v_campaign_id;
  END IF;

  RETURN jsonb_build_object('success', true, 'message', 'Donación aprobada exitosamente');
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
🔔 5. CONFIRMACIONES Y NOTIFICACIONES AUTOMÁTICAS
Confirmación por Correo Electrónico (send-email Edge Function):
Tras registrar el aporte, la función Deno envía un e-mail HTML formal al donante con el resumen del aporte, número de referencia DON-2026-XXXXX y los pasos para el seguimiento.
Notificación Push a la Directora (send-push Edge Function):
Al recibir una donación igual o superior a RD$ 5,000.00, la Edge Function notifica instantáneamente al teléfono móvil de la Directora.
Emisión de Certificado Deducible de Impuestos (PDF):
Al ser aprobada en el panel, el sistema genera automáticamente un PDF firmado digitalmente por la institución para fines fiscales.
